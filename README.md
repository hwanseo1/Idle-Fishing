## ⭐ 핵심 구현 & 문제 해결

### 1. 보상 효과 파이프라인 — OCP(개방·폐쇄 원칙)
자동낚시 보상에 곱해지는 효과(다중 포획, 배 스킬, 서버 배수)를 `IRewardModifier` 구현체로 분리하고 `RewardPipeline`이 순차 적용.
- **새 효과 추가 = 구현체 1개 + 등록 1줄**, 보상 계산 본체는 수정하지 않음.
- 각 효과는 `RewardContext`만 받아 계산 → 컨트롤러 내부를 모름(의존성 격리).

### 2. 인터페이스 + Dummy + 어댑터 — DIP & 팀 협업
선원·골드·재료·미니게임을 인터페이스로만 정의하고, 구현이 없으면 `Dummy*`로 단독 동작.
- 다른 팀원 모듈 완성 전에도 **독립 개발·테스트** 가능.
- 결합 시 어댑터가 타입 차이까지 흡수 → **남의 코드 0줄 수정**.

### 3. LiveOps 인프라 — 서버에서 부팅 통제 (3단 fallback)
PlayFab Title Data로 버전/점검/리모트컨피그를 받아 부팅을 통제.
- 라이브 → PlayerPrefs 캐시 → 동봉 SO(보수값)의 **3단 fallback**으로 서버가 끊겨도 graceful 부팅.
- `VersionGate`는 네트워크·Unity 무관 **순수 함수**(semver 정수 비교) → 단위 테스트 용이.
- **재빌드·재설치 없이 서버 값만으로** 버전 게이팅·점검·밸런싱.

### 4. 강화·재화를 서버 권위로 전환 (동기 → 비동기 승격)
강화 레벨·골드 차감·배 해금을 로컬에서 **PlayFab CloudScript 서버 권위**로 전환.
- 동기 계약(`bool`)을 비동기(`Action<bool>`)로 승격하되 기존 `Try*`는 무서버 폴백으로 보존.
- 비관적 UX(버튼 잠금 → 서버 응답 → 반영)로 단순·정확 우선.

### 🐞 기억에 남는 디버깅
- **보스전 기여도 누수**: 이벤트는 전환 순간만 잡는다는 점을 놓침 → 보스 판정을 `StartLoop` 단일 진입점으로 일원화.
- **재시작 시 레벨만 초기화**(골드는 정상): 비대칭 증상으로 **캐시 선(先)로드 레이스**를 역추적 → 권위 데이터는 서버 명시 재조회로 로드.
- **강화 시 재료 미차감**: 코드는 완성됐으나 SO 데이터가 비어 있었음 → "배관 완성 ≠ 기능 동작" (데이터드리븐의 양면성).
